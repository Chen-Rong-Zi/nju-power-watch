# nju-power-watch 体面谢幕设计

## 概述

因学校缴费系统（epay）对查询接口实施配额限制，项目已无法继续为全校宿舍提供数据采集服务。本项目以"体面关闭"为目标：**在 njupower.top 域名有效期内发布死亡公告**，站点保留历史数据至域名到期，仓库归档为只读存档，社区（issue）逐一收尾，全站以**黑白色调**作为纪念基调。

**一句话**：不是直接拔网线，而是发布温情告别 + 整站黑白纪念 + 保留数据可访问 + 归档仓库，让项目完整、体面地谢幕。

## 背景与现状

- **站点**：`njupower.top`（GitHub Pages + CNAME），当前在线，数据截至 2026-08-05/08。
- **仓库**：`Chen-Rong-Zi/nju-power-watch`（public），master 分支。
- **数据**：约 333MB 历史数据（仙林 129M / 鼓楼 52M / 浦口 22M / 苏州 20M / summaries 111M），约 1.7 万间房间。
- **工作流**：3 个 GitHub Actions（每日 14:00 查询、手动查询、每月 4 次房间扫描）。
- **采集现状**：登录仍成功（NJUlogin 适配后），但 **epay 查询接口实施配额限制，超过阈值后返回「错误查询房间信息失败」（HTTP 层 502）**。最近一次运行 4338 间仅成功 1619（37.3%），低于 90% 可靠性阈值，大规模采集已不可行。
- **社区**：开放 issue #30（比喻招募）、#33（08-08 自动失败告警）。

## 对抗史（完整版 · 用于 docs/about.md 谢幕段落）

### 最初 · 2026.05
校园集市首次宣传，每日 14:00 自动采集全校电费。默认并发 24，一次跑完全校宿舍。

### 对抗一 · 登录验证码 / 滑块 → 验证码识别
auth.nju 登录页开始出现验证码，随后升级为滑块。项目集成云码验证码识别 API，2026 年 7 月进一步集成 NJUlogin 适配滑块登录流程。直到项目结束，登录始终成功。

### 对抗二 · 查询限流 → 限流对抗策略（多轮迭代）
epay 查询接口开始限流（RateLimitedError）。项目历经多轮迭代：
- v1：分批查询 + 自动恢复 + 请求间隔（#23，后因故 revert 重做）
- v2：单批次 + 1 并发 + 0.5s 间隔 + 日志增强（#25）
- 并发数 24 → 10 → 1；单批约 4300 间；工作流超时上限 130 → 360 → 480 分钟
- 2026-08-04 epay 更新限流机制，原有方法全部失效，数据采集中断约 48 小时，适配后恢复

### 终局 · 查询配额限制，采集不再可行
epay 查询接口对单会话内的查询次数实施配额限制：当查询量超过阈值后，接口返回业务错误「错误查询房间信息失败」（HTTP 层表现为 502 Bad Gateway）。在全校约 1.7 万房间的采集规模下，该限制使单轮采集成功率骤降至 37.3%（最近一次运行 4338 间中仅 1619 间成功），低于 90% 的可靠性阈值，大规模数据采集已不可持续，项目遂停止服务。

### 整站黑白色调纪念（D12/D13）

- **全站黑白**：`html { filter: grayscale(100%); }` 一键变灰，覆盖全部页面。站点共有 **5 个 HTML 页面**（首页 + 4 功能页；「关于」是首页的 modal，随首页自动黑白，无需单独处理）
- **注入方式**：新建共享 `docs/css/shutdown.css`（仅含一行灰度滤镜样式），**5 个页面（首页 + 4 功能页）的 `<head>` 各加一行 `<link rel="stylesheet" href="css/shutdown.css">`**；**不修改任何现有 CSS 文件**；回退 = 删掉各页那一行 `<link>`
  - 说明：黑白样式**独立于** `shutdown-banner.js`（首页不需要 banner 脚本，但不能缺黑白样式，故样式独立成文件、全页面引用）
- **图表黑白（D13）**：Chart.js / ECharts 的系列颜色走**灰阶色板**（深浅灰 + 线型/虚实区分系列），保证黑白下多系列仍可分辨；由滤镜 + 灰阶配置双重保障
- **验证项**：`filter` 作用于 `html` 会影响 `position: fixed` 子元素——需验证站点固定导航是否错位，若有则调整（改用 `body` 或包裹容器）

## 边界与不变量

- **push 纪律**：任何 push（代码、文档）均须用户逐次批准；本地 commit 不在此限
- **归档不可逆**：仓库归档为 read-only 操作，执行前须用户明确批准；归档后 Pages 若停止服务则回退
- **数据不删**：333MB 历史数据原样保留，不做清理
- **workflows 不改**：不删除/禁用工作流文件，依赖归档自动停跑
- **域名不续费**（隐含）：站点生命周期以域名有效期为准
